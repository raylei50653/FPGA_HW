# HW3 VGA 掃描規格

## 1. 目標

以 VGA 掃描（640×480@60）在螢幕上顯示圖形，分兩個模式，以 BTNU 切換。每色 1 bit 只是基本模式的
要求，旋轉多面體（Bonus）不限色深：內部全程是 RGB888，VGA 輸出位元數由 generic 決定（1 ~ 8 bit），
HDMI 輸出用 YCbCr 4:2:2（每個分量 8 bit）。EGO-XZ7 沒有 VGA 接頭，目前只從 HDMI 輸出；VGA 輸出級（⑧）以註解保留在
程式裡（標 `[VGA]`），外接 VGA 時取消註解，兩個輸出級可同時使用。

| 模式 | 內容 | 對應作業 |
|---|---|---|
| 基本（reset 後） | R、G、B 三個矩形色塊，位置與大小可任意設定（generic），重疊處加色混合 | 基本要求 |
| 旋轉多面體 | 立方體、八面體、十二面體在 3D 空間中翻滾；BTND 切換「實心打光 + 稜線」與「全息點雲」兩種樣式，可調轉速與方向 | Bonus：複雜圖案 |

多面體的每個像素由一條固定點管線即時算出「這條視線從哪個面進入、從哪個面離開」，**不使用
framebuffer**，也不需要畫三角形、排序深度或存點表。

- 目標板：e-elements EGO-XZ7（`xc7z020clg484-1`，100 MHz），腳位見 `constraints/HW_3.xdc`
- 語言：VHDL（`ieee.numeric_std`）；設計為 VHDL-93，測試檔需以 VHDL 2008 編譯
- Top 模組：`HW_3`，測試檔：`HW_3_tb`
- 單一時脈域（100 MHz），像素以時脈致能 `pix_ce` 推進；送給 ADV7511 的 25 MHz 像素時脈也是由
  100 MHz 分頻的暫存器輸出（§6.5）
- 合成出一組與腳位無關的 RGB888 視訊串流，HDMI 輸出級（與註解掉的 VGA 輸出級）從這裡取（§6.4、§6.5）

## 4. 視訊時序

標準 640×480@60 的像素時脈是 25.175 MHz，本設計用 100 MHz / 4 = 25 MHz，行頻 31.25 kHz、幀率
59.5 Hz，在一般螢幕的容許範圍內。

| | 可視 | 前廊 | 同步 | 後廊 | 總計 |
|---|---|---|---|---|---|
| 水平（像素） | 640 | 16 | 96 | 48 | 800 |
| 垂直（行） | 480 | 10 | 2 | 33 | 525 |

`HW_3_timing` 的輸出全部由同一組計數值解出並經暫存器輸出，所以 `x`、`y`、`de`、`hs`、`vs` 彼此
對齊；`hs`、`vs` 內部一律為高電位有效。`frame_start` 標出垂直遮沒的第一個像素（`y = 480`、
`x = 0`），角度與矩陣在這之後更新，整幀畫面都用同一組係數。

## 5. 多面體管線（`HW_3_solid`）

### 5.1 數學：每個像素是一條光線

凸多面體是 F 個半空間的交集：點 P 在形體內 ⇔ 對每個面 k，`n_k · P ≤ a`。`n_k` 是第 k 個面的單位
外法向量，a 是內切球半徑（正多面體每個面到中心的距離都相同）。

採正交投影，座標系為螢幕 x 向右、y 向下、z 往螢幕裡。像素 d = (dx, dy)（相對形狀中心）對應一條
光線 P = (dx, dy, z)，代進第 k 個面：

```text
nx·dx + ny·dy + nz·z ≤ a   →   z_k = (a − nx·dx − ny·dy) / nz
nz < 0（正面，朝向觀眾）：光線要在 z ≥ z_k 才在面的內側 → 進入點
nz > 0（背面）          ：z ≤ z_k                       → 離開點
nz ≈ 0（側面）          ：與 z 無關，退化成 2D 半平面 nx·dx + ny·dy ≤ a
```

光線穿過多面體 ⇔ `max(正面 z_k) ≤ min(背面 z_k)` 且所有側面條件成立；看到的是 z_k 最大（最後
一個進入）的那個正面，光線從 z_k 最小的那個背面離開。這就是凸多面體的光線投射，不需要頂點、
三角形或深度緩衝；而且凸多面體的每條光線只會穿過表面兩次，進入點與離開點就是全息點雲要的兩個
交點（§5.7）。

重點是 z_k 對 (dx, dy) 是一次式，係數只跟這一幀的旋轉有關：

```text
z_k = A_k + B_k·dx + C_k·dy      A_k = a/nz、B_k = −nx/nz、C_k = −ny/nz
v   = W · (dx, dy, 1)           W 為 F×3 矩陣，第 k 列 (B_k, C_k, A_k)
```

所以和 2D 版的旋轉多邊形一樣是「矩陣 × 向量」：每幀在垂直遮沒算一次 W（含除法），每個像素只做
2F 個乘法、再取 max／min。側面的列改成 (nx, ny, −a)，v ≤ 0 才在形狀內。

### 5.2 形體與旋轉

| `SOLID` | 形體 | 面數 F | 面法向量方向 | 內切球 / 外接球 |
|---|---|---|---|---|
| 0 | 立方體 | 6 | ±x、±y、±z | 1/√3 ≈ 0.577 |
| 1 | 八面體 | 8 | (±1, ±1, ±1) | 1/√3 |
| 2 | 十二面體 | 12 | (0, ±1, ±φ) 的循環排列 | √((5+2√5)/15) ≈ 0.795 |
| 3 | 二十面體 | 20 | (±1, ±1, ±1) 與 (0, ±1/φ, ±φ) 的循環排列 | 同上 |

φ = (1+√5)/2。法向量在 elaboration 時以 `math_real` 算好並正規化。二十面體預設沒有用到，把
`SOLID_A` 的某一項改成 3 即可（比較樹已預留 32 個葉節點）。

旋轉為 `R = Rx(α) · Ry(β) · T`：

- T = Rx(30°)·Ry(40°) 是固定的初始傾斜，在 elaboration 時套進法向量表 N0，角度為 0 時也同時看得到
  好幾個面（不然立方體正對觀眾就只是一個正方形）
- 每幀先繞 y 轉 β、再繞 x 轉 α，各是一次 2D 旋轉：

```text
Ry(β)：x' = cβ·nx + sβ·nz          z' = cβ·nz − sβ·nx
Rx(α)：y'' = cα·ny − sα·z'         z'' = sα·ny + cα·z'
```

### 5.3 光照

平面著色（每個面一個顏色）。光源方向（指向光源）L = normalize(−0.45, −0.65, −0.60)，即左上前方：

```text
亮度 I = 1/4 + 3/4 · max(0, n · L)        （8 bit：64 ~ 255）
顏色   = BASE_RGB × I
```

每個面的顏色每幀算一次存在表裡，像素管線只要用看到的面編號查表。

### 5.4 定點格式

位元寬依 DSP48E1 的埠來定：乘法器是 25 bit × 18 bit（有號），累加器 / P 暫存器 48 bit。

| 數值 | 格式 | 位元 | 放在 |
|---|---|---|---|
| sin ROM、N0、轉好的法向量 | Q1.14 有號（1.0 = 16384） | 16 | 18 bit 埠 |
| 1/\|nz\| | Q9.14 無號（\|nz\| ≥ 1/256，所以 ≤ 256） | 23 | 25 bit 埠 |
| 內切球半徑 a | 像素 × 2^8，有號 | 17 | 18 bit 埠 |
| B、C | Q9.14 有號 | 24 | 25 bit 埠 |
| A | 像素 × 2^14，有號 | 32 | C 埠（48 bit） |
| d | 整數像素，有號 | 13 | 18 bit 埠 |
| v = A + B·dx + C·dy | 像素 × 2^14，有號，\|v\| < 2^34 | 40 | P 暫存器 |
| 比較樹的深度 | 像素 × 2^4（取 v 的第 10 ~ 35 位元） | 26 | fabric 暫存器 |
| 切向量 t1、t2 | Q1.14 有號 | 16 | 18 bit 埠 |
| 面座標係數 Ux、Uy、Vx、Vy | Q9.14 有號 | 24 | 25 bit 埠 |
| 面座標係數 U0、V0 | 像素 × 2^14，有號 | 32 | C 埠 |
| 面座標 u、v | 像素 × 2^14，有號 | 40 | P 暫存器 |

a 只留 8 位小數是為了放進 18 bit 埠。所有面用同一個 a，等於整個形體縮放不到 1/512 像素，面與面
之間仍然完全一致。比較樹只需要分出「哪個面比較遠」，1/16 像素的深度解析度已經足夠（模擬中與
浮點數參考模型的差異只出現在面的交界上，見 §9），比較器從 40 bit 減到 26 bit，進位鏈從 10 個 CARRY4 減到
7 個。

\|nz\| < 1/256 的面當成側面，不做除法，避免 1/nz 爆掉。這種面幾乎與視線平行，在畫面上最多佔
`R·|nz| < 0.4` 像素寬，忽略 z 項的誤差看不出來。

### 5.5 每幀計算 W：一個 DSP 的乘累加器

每幀的運算量很小（十二面體約 200 個乘法），但時間很多（垂直遮沒 144 000 個 clk），所以每個形體
只用**一個** DSP48E1，當成乘累加器照固定排程表逐拍餵運算元：

```text
第 s 拍送運算元（A、B 暫存器）→ s+1 拍乘積進 M 暫存器 → s+2 拍 P = M（載入）或 P + M（累加）
→ 第 s+3 拍讀 P。沒事做的拍子送 0 × 0 累加，P 保持不變；減法改成把運算元先取負號
```

四個暫存器與累加全在 DSP 內部（綜合報告：`((C:0x0) or P)+(A2*B2)`），fabric 只剩運算元多工器與
讀結果的四捨五入。`load` 在 `frame_start` 後一拍送出，前兩拍查 ROM 取得 cα、sα、cβ、sβ，之後每個面
跑 62 拍：

| 送運算元（拍） | 運算 | 讀結果（拍） |
|---|---|---|
| 0、1 | cβ·nx0 載入、sβ·nz0 累加 | 4：nx' |
| 2、3 | cβ·nz0 載入、−sβ·nx0 累加 | 6：w = 轉完 Ry 的 z |
| 4、7 | cα·ny0 載入、−sα·w 累加（等 w 算好） | 10：ny' |
| 8、9 | sα·ny0 載入、cα·w 累加 | 12：nz' |
| 10、11、13 | Lx·nx'、Ly·ny'、Lz·nz' 累加（等 nz'） | 16：n · L |
| 13 ~ 41 | 依 nz' 分類；恢復式除法 2^28 / \|nz'\|，每拍一位（fabric，16 bit 減法） | 42 起：1/\|nz'\| |
| 14 ~ 23 | 切向量 t1 照 0 ~ 9 的方式轉（MAC 在除法期間空著，剛好用來轉切向量） | 18 ~ 26：t1' |
| 26 ~ 35 | 切向量 t2 同上 | 30 ~ 38：t2' |
| 17、18 | 夾在 0 ~ 1；亮度 = 64 + 3·lit / 256（移位相加，不用乘法器） | |
| 42、43、44 | q·nx'、q·ny'、q·a 各自載入 | 45、46、47：B、C、A |
| 45、46、47 | 底色 × (亮度 + 1)，三個通道 | 48、49、50：顏色 |
| 48 | 依正面／背面決定 A、B、C 的正負號（側面改用 (nx, ny, −a)） | |
| 49 ~ 56 | B·t1z 載入、1.0·t1x 累加，依此類推 | 53、55、57、59：Ux、Uy、Vx、Vy |
| 57、58 | (A / 256)·t1z、(A / 256)·t2z | 60、61：U0、V0；第 61 拍寫進表格 |

排程是固定的，側面也照跑（除法結果不用），不需要分支。十二面體共 2 + 12 × 62 = 746 個 clk
（7.5 µs）；即使 `PIX_DIV = 1`，垂直遮沒也還有 36 000 個 clk。reset 後到第一次算完之前，`inside`
一律為 0（基本模式本來就不用）。

第一版每種運算各用一組乘法器，每個形體 13 個 DSP；改成共用後只剩 1 個。另外這段序列每幀只跑一次，
但仍以 100 MHz 做時序分析，所以每拍只放一層運算（例如 n · L 的夾值與縮放分在兩拍）。

### 5.6 像素管線：每列兩個串接的 DSP

每級一個 `pix_ce`：

| 級 | 運算 | 資源 |
|---|---|---|
| P1 | `d = (x − CX, y − CY)` | 2 個減法器 |
| P2 | `pa_k = A_k + B_k·dx` | 每列一個 DSP48E1：B·dx 進乘法器、A 進 C 埠（`C+A*B`） |
| P3 | `v_k = pa_k + C_k·dy` | 每列第二個 DSP48E1：pa 經 PCIN 串接進來（`PCIN+A*B`） |
| P4 | 取 v 的 26 bit 當葉節點：正面 → 候選深度、背面 → 深度上限、側面 → `v ≤ 0` | |
| T1 ~ T5 | 比較樹，每層一級：取最大的正面深度（與面編號）、最小的背面深度、側面條件取 AND | 2^`TREE_LV` − 1 個節點 |
| P5 | `max ≤ min` 且側面都成立 → 在形狀內；以面編號查顏色表 | |
| H1 | 以進入面、離開面的編號讀面座標係數 | LUTRAM（兩個讀取埠，取代 F 選 1 的多工器） |
| H2 | 兩個交點的 `U0 + Ux·dx`、`V0 + Vx·dx` | 4 個 DSP48E1（`C+A*B`） |
| H3 | 再加 `Uy·dy`、`Vy·dy` | 4 個 DSP48E1（`PCIN+A*B`） |
| H4 | 以 (u, v) 所在格子查雜湊，判斷是不是點雲上的點 | XOR、旋轉、一個 24 bit 加法 |

`A + B·dx + C·dy` 剛好是 DSP48E1 的「乘加 + 串接」：第一個 DSP 的 P 直接走專用的 PCIN 線進第二個
DSP 的後加法器，不經過 fabric，所以 F 個三輸入 40 bit 加法器、以及乘積與 v 的暫存器全部消失在 DSP
裡（`dx`、乘積、`pa`、`v` 分別成為 DSP 的 B、M、P 暫存器）。

延遲 9 + `TREE_LV` = 14 個像素，所以 ⑥ 把座標與同步訊號也延遲 14 個像素。比較樹固定 5 層，三個
形體延遲相同；沒用到的葉節點是常數，綜合時會被消掉。比較樹每層都加暫存器：FPGA 每個 LUT 旁邊
就有正反器，多一層暫存器幾乎不佔面積，卻讓每級只有一個 26 bit 比較（一條 7 個 CARRY4 的進位鏈）。

### 5.7 全息點雲

只用稀疏的點描出表面，正面與背面的點同時畫出來，形體看起來像半透明的全息投影。不需要點表：

```text
進入點 P_f = (dx, dy, z_f)、離開點 P_b = (dx, dy, z_b)   ← 比較樹已經算出是哪兩個面
面座標 u = t1 · P、v = t2 · P                            ← t1、t2 為該面的兩個切向量
       = t1x·dx + t1y·dy + t1z·(A + B·dx + C·dy)
       = U0 + Ux·dx + Uy·dy                               ← 又是一次式，每幀算一次係數
```

- 每個面上鋪 8 × 8 像素的格子：u、v 的第 17 位以上是格子編號，第 12 ~ 16 位是格子內的 1/4 像素位置
- 以 `正/背面 & 種子 & 面編號 & 格子編號` 查雜湊：低 8 位元 < 192 才放點（75%），另外 6 位元決定
  點在格子內的位置（偏離中心最多 ±0.22 格），點不會排成死板的格子
- 像素的 (u, v) 離點不超過 2/4 像素就點亮。點黏在面上，跟著形體一起轉
- 雜湊只用 XOR、旋轉與一個 24 bit 加法，不佔 DSP；正面與背面用不同的種子，兩層的點不會重疊

參數依網頁原型調整後的結果：點間距 8 px、正面與背面的保留率都是 75%，背面的點和正面同色。

## 6. 合成與輸出

### 6.1 基本模式：RGB 色塊

三個矩形，各自只點亮一個顏色通道。預設把畫面直切三等分、由左到右紅綠藍，填滿整個畫面、不留黑：

| 色塊 | 預設左上角 | 預設寬 × 高 | 顏色 |
|---|---|---|---|
| R | (0, 0) | 214 × 480 | 紅 |
| G | (214, 0) | 212 × 480 | 綠 |
| B | (426, 0) | 214 × 480 | 藍 |

640 不能被 3 整除，寬取 214、212、214，讓兩條交界都落在偶數 x：HDMI 的 YCbCr 4:2:2 每對像素
（偶、奇）共用色度（§6.5），交界若在一對中間，交界的像素會帶到隔壁的顏色。改成較小的色塊時，沒蓋到
的地方是黑色。

位置與大小由 generic `R_X` … `B_H` 任意設定（elaboration 時檢查不得超出可視區）。判斷式為
`X ≤ x < X + W 且 Y ≤ y < Y + H`，三色各自獨立，所以把色塊設成重疊時，重疊處會自然出現加色
混合（R + G = 黃、G + B = 青、R + B = 洋紅、三色 = 白）。基本模式不使用多面體管線，但座標一樣取
⑥ 的延遲版本，兩個模式的輸出時序完全相同，切換時畫面不會偏移。

### 6.2 旋轉多面體模式：畫面配置

| 形狀 | 中心 | 外接球半徑 | 每幀轉速（x 軸, y 軸） | 底色 |
|---|---|---|---|---|
| 0 立方體 | (106, 240) | 100 | (+2, +3) | `FF0000` |
| 1 八面體 | (320, 240) | 100 | (+3, −2) | `00FF00` |
| 2 十二面體 | (533, 240) | 100 | (−1, +2) | `0000FF` |

位置與半徑隨解析度縮放（中心為 `H_ACTIVE` 的 1/6、1/2、5/6，半徑 = `H_ACTIVE × 5/32`），三個
外接球互不重疊。背景為黑色，稜線為白色 `FFFFFF`。

每幀繞 x、y 軸各轉 `SPIN × 2^speed_sel` 步（一圈 1024 步），反轉時兩軸都取負號。兩軸轉速不同，
形體會不斷翻滾，看得到每一個面。

### 6.3 稜線與樣式

⑦ 為每個像素產生兩個標籤：`在形狀內 & 形狀編號（2 bit）& 面編號（5 bit）`，一個用看到的面（正面），
一個用光線離開的面（背面），背景為 0。兩個標籤打包成 16 bit，存進兩個行緩衝（各 640 × 16 bit，
仍是各一個 RAMB18），記下上一行、上兩行同一欄的標籤；標籤和 (x−1)、(x−2)、(y−1)、(y−2) 任一個
不同，這個像素就是稜線。正面標籤描出看得見的稜線與輪廓，背面標籤描出被擋住的稜線。

| `holo` | 按 BTND 切換 | 畫面 |
|---|---|---|
| `0` | 實心打光 + 稜線（預設） | 正面稜線用白色，其餘形狀內像素用該面打光後的顏色 |
| `1` | 全息點雲 | 正面稜線白色；正面或背面落在點上的像素用形體的顏色；背面稜線畫成形體顏色的虛線（`(x + y) mod 4 < 2`）；其餘為黑色 |

合成分 3 級：C1 選出最上層的形狀（編號小的在上層）並讀寫第一個行緩衝，C2 讀寫第二個行緩衝並記下
左邊兩個像素，C3 判斷稜線、套樣式，`de = 0` 時輸出黑色。

### 6.4 輸出與色深

⑦ 的輸出 `stream_rgb`（RGB888）、`stream_de`、`stream_hs`、`stream_vs` 是與腳位無關的視訊串流，
同步為高電位有效。⑧ 只做兩件事：取各色高 `*_BITS` 位元、依 `SYNC_ACTIVE_LOW` 反相同步。

| 輸出 | 色深 | 畫面 |
|---|---|---|
| 每色 1 bit（預設） | 8 色 | 基本模式的要求，純色色塊不受影響；旋轉多面體不受此限，全息點雲只用純色與白色仍完全相同，實心打光只剩亮面與暗面兩階 |
| 電阻 DAC，每色 2 ~ 8 bit | 64 色 ~ 1677 萬色 | 實心打光的明暗依位元數呈現 |
| HDMI（⑨，目前唯一的輸出） | YCbCr 4:2:2 | 亮度每像素 8 bit，色度兩個像素共用（§6.5） |

螢幕端每個顏色是 75 Ω 負載、滿刻度 0.7 V。1 bit 輸出時，3.3 V 腳位串約 270 Ω 電阻：
3.3 × 75 / (270 + 75) ≈ 0.72 V；多位元時用 R-2R 或二進位加權電阻網路。

### 6.5 HDMI 輸出級

EGO-XZ7 的 HDMI 接頭前面是 ADV7511（HDMI 發送晶片，《EGO-XZ7 硬體手冊》V1.2 表 14），TMDS 編碼與
序列化由它負責。FPGA 送平行的影像資料、hs、vs 與像素時脈，並在開機後經 I2C 設定它。

**為什麼是 YCbCr 4:2:2**：ADV7511 的輸入匯流排有 36 bit（D35..D0），24 bit RGB 4:4:4 時 R 在 D35..28、
G 在 D23..16、B 在 D11..4。EGO-XZ7 只把 D23..D0 接到 FPGA（電路圖網路 HDMI_D0..23），R 根本收不到。
第一次上板就是這樣：背景全紅（D35..28 沒接、讀成 1），紅色塊變黃（R 跑到 G）、綠色塊變洋紅
（G 的低 4 bit 跑到 B 的高 4 bit），藍色塊幾乎看不到。所以改用 ZedBoard 的接法：16 bit YCbCr 4:2:2
（輸入 ID 1），只用到 D23..D8，ADV7511 先補回 4:4:4、再用內建的 CSC 轉回 RGB 送出。EGO-XZ7 的
HDMI_D0..15 和 ZedBoard 的 HD-D0..15 是同一組 FPGA 腳位，設定照 ZedBoard 的 Linux 裝置樹
（`yuv422`、style 1、right justification）與 Linux `adv7511_drv.c` 的 CSC 係數。

```text
 stream_rgb ─► RGB→YCbCr（第一拍）─► 4:2:2（第二拍）─► hd_reg（IOB）─► D23..16 = Cb / Cr、D15..8 = Y
 stream_hs/vs ─► 延遲一拍 ─────────────────────────► hhs_reg / hvs_reg ─► HSYNC / VSYNC
 div_cnt ──────► hclk_reg ────────────────────────────────────────────► CLK（上升緣取樣）
 HW_3_hdmi_cfg ───────────────────────────────────────────────────────► SCL / SDA（I2C 位址 0x72）
```

**RGB → YCbCr**：BT.709、有限範圍（Y 16 ~ 235、Cb / Cr 16 ~ 240），和 ADV7511 的 CSC 係數同一套
標準。係數乘 256 取整數，先加偏移量讓被除數不為負，除以 256 就是右移：

```text
Y  = (4224  +  47 R + 157 G +  16 B) / 256
Cb = (32896 -  26 R -  87 G + 112 B) / 256
Cr = (32896 + 112 R - 102 G -  10 B) / 256
```

黑色是 (16, 128, 128)、白色是 (235, 128, 128)。**4:2:2**：每行第一個可視像素送 Cb，之後 Cr、Cb
輪流（和 ADI 的 `ad_ss_444to422` 相同），色度直接取該像素的值、不濾波；遮沒期間輸出 0。D7..D0 不用，
固定輸出 0。整條路徑比 VGA 多一拍：串流到腳位共 2 個像素。

**資料與時脈**：`hd_reg`、`hhs_reg`、`hvs_reg` 在 `pix_ce` 更新，像素時脈
`hclk_reg` 在 `div_cnt >= PIX_DIV / 2` 時為 1。`PIX_DIV = 4` 時，資料在 `div_cnt = 0` 的 clk 換值，
時脈在 2 個 clk（20 ns）之後才上升、再 20 ns 下降，ADV7511 在上升緣取樣，setup 與 hold 各有半個
像素。這些暫存器都放進 IOB（xdc 的 `IOB TRUE`），各腳位的輸出時間一致，不需要 I/O 時序約束，也
不需要 MMCM 或 ODDR。

**ADV7511 設定（`HW_3_hdmi_cfg`）**：I2C 主控端，SCL 100 kHz，每筆寫入是 START、0x72、暫存器位址、
資料、STOP，每個 byte 後讀 ACK。開機等 `HDMI_CFG_DELAY`（約 168 ms）後寫入下表（47 筆），寫完再等
同樣的時間重寫一次，一直重複：螢幕晚插上、或 ADV7511 因 HPD 改變而重設時，下一輪就會恢復。最近
一輪全部收到 ACK 時 LD6 亮。

| 暫存器 | 值 | 用途 |
|---|---|---|
| 0xD6 | 0xC0 | HPD 視為一直有接，不必等熱插拔偵測 |
| 0x41 | 0x10 | 開啟電源 |
| 0x98、0x9A、0x9C、0x9D、0xA2、0xA3、0xE0、0xF9 | 0x03、0xE0、0x30、0x61、0xA4、0xA4、0xD0、0x00 | 手冊要求的固定值 |
| 0x15 | 0x01 | 輸入 ID 1：YCbCr 4:2:2、分離同步 |
| 0x16 | 0x38 | 輸出 4:4:4、每個分量 8 bit、輸入樣式 1（暫存器值 2）、輸出 RGB |
| 0x48 | 0x08 | 輸入資料靠右對齊（16 bit 在 D23..D8） |
| 0x17 | 0x61 | vs、hs 低電位有效，4:3，DE 產生器開啟 |
| 0x35 ~ 0x3A | 0x24、0x23、0x05、0x00、0x1E、0x00 | DE 產生器：hsync 延遲 144、vsync 延遲 35、寬 640、高 480 |
| 0x1A | 0x24 | CSC 進入更新模式（0x1A[5]） |
| 0x18 ~ 0x2F | 0xC7、0x34 … 0x1B、0x77 | CSC：0x18[7] 開啟、0x18[6:5] = 2 縮放 ×4；12 個 13 bit 係數 0x0734、0x04AD、0x0000、0x1C1B、0x1DDC、0x04AD、0x1F24、0x0135、0x0000、0x04AD、0x087C、0x1B77（BT.709 有限範圍 YCbCr → RGB） |
| 0x1A | 0x04 | 離開更新模式 |
| 0xAF | 0x04 | DVI 模式（只有影像，沒有聲音與 InfoFrame） |
| 0xBA | 0x60 | 輸入時脈不延遲 |

以紅色 (255, 0, 0) 驗算：YCbCr = (63, 102, 240)，經 CSC 得 R ≈ 256（截成 255）、G ≈ 0.6、B ≈ −0.3（截成 0）。

**上板紀錄**：
1. 24 bit RGB（輸入 ID 0）：位置、同步與 DE 產生器都正確，但顏色錯，原因見上面「為什麼是 YCbCr 4:2:2」
2. YCbCr 4:2:2：待上板確認。若顏色只是紅藍互換，把 `cr_sel` 在遮沒期間的初值改成 1（每行先送 Cr）

**DE 產生器**：板子沒有把 DE 接到 FPGA，ADV7511 依 hs、vs 自己算出可視區：hsync 前緣之後
`H_SYNC + H_BP` 個像素開始、寬 `H_ACTIVE`；vsync 前緣之後 `V_SYNC + V_BP` 行開始、高 `V_ACTIVE`。
這些值由 `HW_3` 的時序 generic 算出，換解析度不必改表。若上板後畫面整體偏移幾個像素或幾行，先調
`H_DE_DELAY`、`V_DE_DELAY`（暫存器 0x35 ~ 0x36 的計算起點以 ADV7511 Programming Guide 為準）。

**限制**：像素時脈由 100 MHz 分頻，只能是 100 / `PIX_DIV` MHz；720p 的 74.25 MHz 要改用 MMCM 產生
像素時脈，整個設計改跑在那個時脈上（`PIX_DIV = 1`），時脈輸出改用 ODDR。

## 7. 操作

| 輸入 | 功能 |
|---|---|
| BTNC | reset：回到基本模式、正轉、轉速 ×2、實心打光，角度歸零 |
| BTNU | 模式：基本色塊 ↔ 旋轉多面體 |
| BTNL | 轉速 ×1 → ×2 → ×4 → ×8 → ×1 |
| BTNR | 反轉 |
| BTND | 樣式：實心打光 + 稜線 ↔ 全息點雲（§6.3） |
| SW0 | 撥上暫停旋轉，撥下繼續 |

BTNL、BTNR、BTND、SW0 只影響旋轉多面體模式；在基本模式按下也會記住，切過去就生效。角度在基本
模式下照樣累加，所以切回旋轉多面體時不一定是初始姿態。

| LED | 意義 |
|---|---|
| LD0 | 旋轉多面體模式 |
| LD1 | 轉動中（SW0 撥下） |
| LD2 | 反轉 |
| LD4..LD3 | `speed_sel` |
| LD5 | 全息點雲 |
| LD6 | ADV7511 設定成功（最近一輪 I2C 全部收到 ACK） |
| LD7 | 心跳，每 32 幀切換一次（約 1 Hz 閃爍），沒接螢幕也能確認時序在跑 |

按鈕經兩級同步，連續 `DEBOUNCE_CYCLES` 個 clk 穩定才更新，只在按下的瞬間觸發一次。SW0 是電位
訊號，只做兩級同步。

5 顆按鈕都有用途，因此暫停改用開關：暫停本來就是「狀態」而不是「動作」，用撥桿也更直覺。

## 8. 資源與時序

Vivado 2018.3 綜合結果（xc7z020，HDMI 輸出、VGA 註解掉，僅供參考）。「加 HDMI 前」是只有 1 bit VGA
輸出的版本；「第一版」是同樣功能、但沒有照 DSP48E1 結構寫的版本，留著對照：

| 資源 | 用量 | 佔比 | 加 HDMI 前 | 加點雲前（含藍噪聲抖動） | 第一版 |
|---|---|---|---|---|---|
| Slice LUT | 5561 | 10.5% | 5086 | 3709 | 6089 |
| 　其中 LUTRAM | 965 | | 890 | 180 | |
| Slice Register | 5605 | 5.3% | 5326 | 4191 | 7218 |
| DSP48E1 | 79 | 35.9% | 79 | 55 | 91 |
| Block RAM（RAMB18） | 8 | 2.9% | 8 | 9 | 8 |
| I/O 腳位 | 44 | 22.0% | 20 | | |
| WNS @ 100 MHz（綜合後估計） | +2.449 ns | | +2.449 ns | +2.441 ns | +2.106 ns |

- HDMI 用了 29 個腳（24 bit 資料、hs、vs、時脈、SCL、SDA；D7..D0 固定輸出 0），沒有用 MMCM、OSERDESE2
  或額外的 BUFG；RGB → YCbCr 用常數乘法，約 250 個 LUT，沒有用 DSP
- 照 `HW_3.xdc` 跑完 place & route 並產生 bitstream：WNS +0.153 ns、WHS +0.023 ns，全部滿足；HDMI 的
  19 個輸出暫存器都放進 IOB；DRC 沒有錯誤（只剩 DSP 的 DPOP-2 警告）。最差的路徑是 `pix_ce` 扇出到
  `HW_3_solid` 比較樹的時脈致能（0 級邏輯，幾乎全是繞線），和 HDMI 無關

- DSP：像素管線 2 × (6 + 8 + 12) = 52 個算深度、每個形體 8 個算面座標（共 24 個）、每個形體的序列
  1 個。綜合報告的 DSP 模式為 38 個 `C+A*B`、38 個 `PCIN+A*B`、3 個 `(0 or P)+A*B`，加法、串接與
  管線暫存器都在 DSP 內部
- 全息點雲的開銷：24 個 DSP；面座標係數表要用進入面、離開面兩個編號同時讀，綜合成雙讀取埠的
  LUTRAM（約 710 個 LUT），比 F 選 1 的多工器省；背面標籤和正面標籤擠在同一組行緩衝，不多用 BRAM
- 省下來的地方：
  - 序列共用一個乘累加器：91 → 55 個 DSP
  - `A + B·dx + C·dy` 改用 DSP 的 C 埠與 PCIN 串接：26 個 40 bit 三輸入加法器不再佔 LUT，
    乘積與 v 的暫存器也併進 DSP
  - 比較樹的深度 40 → 26 bit：每個節點的暫存器從 86 bit 降到 58 bit
- 記憶體：每個形體的 sin ROM（1024 × 16 bit）放進一個 RAMB18，兩個讀取埠同時讀 sin、cos；兩個行
  緩衝各一個 RAMB18，用 read-first 模式在同一拍讀出上一行、寫入這一行
- 時序：每級只有一個 DSP、一層 26 bit 比較或一次多工，像素管線雖然每 4 個 clk 才前進一次，仍以
  100 MHz 分析也有 2.4 ns 餘裕，不需要 multicycle 約束

### 8.1 還可以再省的地方

`PIX_DIV = 4` 時，像素管線的 76 個 DSP 每 4 個 clk 只用 1 次。改成每個 DSP 在一個像素的 4 個 clk 內
輪流算 4 個面，可以降到 19 個；代價是 `PIX_DIV = 1`（720p 等需要獨立像素時脈的解析度）時不能用，
需要另一套 generic 分支，所以目前沒有做。

## 9. 驗證（`HW_3_tb`）

以真實的 640×480@60 參數（`PIX_DIV = 4`）跑約 9 幀（模擬時間約 150 ms），從 RGB888 串流與
`stream_label` 擷取畫面，結束時印出 PASS／FAIL：

1. **同步時序**：HDMI 的 hs 寬 96 像素、週期 800 像素；vs 寬 2 行、週期 525 行（全程檢查）
2. **基本模式**：reset 後 LD0 熄滅，紅、綠、藍色塊各恰好 214 × 480、212 × 480、214 × 480 像素（合起來
   是整個畫面，沒有黑色），沒有多面體
3. **切換模式**：按 BTNU 後 LD0 亮
4. **參考模型**：測試檔依 §6.2 自己累加角度（只讀 top 層的 `frame_tick` 與轉速、方向設定，順便
   驗證 ④），再以浮點數重做一次光線投射（同樣的法向量、傾斜、旋轉），
   每個形狀外接方框內的每個像素都比對「看到哪個面」，不符的像素不得超過參考面積的 0.5% + 10
   （只會出現在面與面的交界）；每個形狀至少看得到 2 個面
5. **旋轉**：相鄰兩幀畫面不同，轉速 ×8、反轉後仍與參考模型一致
6. **設定**：按 BTNL 兩次、BTNR 一次後 LD4..LD0 = `11111`
7. **全息點雲**：按 BTND 後 LD5 亮，畫面只有黑、白（稜線）與三種純色；測試檔以浮點數重做進入點、
   離開點、面座標與同一個雜湊，加上背面標籤變化的虛線，逐像素比對（正面稜線不比），不符的像素不得
   超過參考點數的 10% + 20（只會出現在點的邊緣）
8. **實心打光**：再按一次回到實心樣式，LD5 熄滅，有稜線、形狀外沒有雜點
9. **輸出級**：每個像素的 HDMI 輸出都等於參考模型把串流轉成的 YCbCr 4:2:2（Cb、Cr 交替的相位與 2 個
   像素的延遲一起驗證）；VGA 接回時，
   標 `[VGA]` 的檢查另外比對 1 bit VGA 輸出與串流各色的最高位元
10. **暫停**：SW0 撥上後 LD1 熄滅，連續兩幀畫面相同
11. **HDMI 像素時脈**（全程）：週期為一個像素，上升緣前後 10 ns 內資料與同步不變
12. **ADV7511 設定**：測試檔裡的 ADV7511 模型（I2C 從端）對每個 byte 回 ACK、記下寫入的暫存器；結束時
    檢查所有寫入都送到 0x72、至少寫完一輪，DE 產生器等暫存器的值正確，LD6 亮（測試檔把
    `HDMI_CFG_DELAY` 縮成 1000 個 clk）

畫面另存成 PPM：`frame_basic`、`frame0`、`frame_fast`、`frame_holo` 各一張 RGB888 串流與一張實際
的 HDMI 腳位輸出的亮度 Y（`*_hdmi.ppm`，灰階），可用影像軟體直接打開檢查。

### 9.1 模擬器

同一個 `HW_3_tb` 可以用兩種模擬器跑，結果相同：

| 模擬器 | 怎麼跑 | 畫面存在 |
|---|---|---|
| Vivado xsim 2018.3 | `.\Manage-FPGA.ps1 create HW3` 後在 Vivado 按 Run Simulation（已設定 160 ms） | `vivado/HW3/HW3.sim/sim_1/behav/xsim/` |
| GHDL 6.0（mcode） | `.\HW3\Run-GHDL.ps1`（安裝：`winget install --id ghdl.ghdl.ucrt64.mcode -e`） | `vivado/HW3/ghdl/` |

GHDL 不必開 Vivado，但 mcode 版本比 xsim 慢很多：一幀約 20 分鐘，整個測試檔約 3 小時。測試檔只用到兩個模擬器都支援的 VHDL-2008 功能：
external name 只指向 top 層的訊號（xsim 2018.3 的 external name 進不了 for-generate 的第 1、2 個
實例，所以角度由測試檔自己累加），也不用 `to_string`（xsim 2018.3 不支援）。

模擬很慢是因為要逐拍模擬每個暫存器：一幀 640×480 是 800 × 525 × 4 ≈ 168 萬個時脈週期，而且
`signed` / `unsigned` 在模擬器裡是逐位元運算的陣列。只想看畫面時，可以把 `PIX_DIV` 設成 1（像素
輸出完全相同，少 3/4 的空轉時脈），或把解析度 generic 調小。
